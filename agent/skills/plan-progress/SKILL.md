# 计划进度条

有当前计划时，每轮修改、检查或汇报都调用本技能。只维护协作工具时同样展示业务计划的实际进度。以 PLAN 中的 `[x]` 和 `[ ]` 计算验收数。[逐函数计数约定](../goal-to-plan/SKILL.md#4-给阶段配验收标准)

1. 按本轮实际结果更新复选框和阶段状态。草案、排版预览或技能维护沿用业务计划的实际完成数。
2. 从仓库根目录执行下面的命令。每次都重新统计总数及各阶段数据。图片只绘制一条灰色横条，计数、百分比和阶段表使用原生 Markdown。已渲染的进度和样式相同时直接复用 PNG。
3. 同一轮工具调用中，脚本成功后直接输出 PNG 像素。最终答复依次放总计和原图链接、内嵌 PNG、完整阶段表。表头沿用“阶段 / 任务与改动 / 已完成 / 完成度 / 状态”。每个阶段都占一行，包括尚未开始的阶段。
4. 业务实施时，在表下按[逐函数的代码排版](../lab-workflow/SKILL.md#4-一次讲清一个函数)展开本轮步骤。维护或收尾时只说明实际改动与当前准备状态。详细验收记录由助手维护，遇到需要用户处理的问题就指出具体位置。

```sh
python3 agent/skills/plan-progress/scripts/render.py
```

脚本默认读取 `agent/PLAN.md`，可用 `--plan 文件路径` 指定另一份计划。清单前后的 `<!-- plan-progress: 简短计划名 -->` 和 `<!-- /plan-progress -->` 可限定计数范围。按粗体标题或 Markdown 小标题分组，阶段状态取自 PLAN 的“阶段 / 状态”表，两处使用相同名称或相同圈号。单阶段清单也可直接使用。代码块中的示例会被跳过。

阶段百分比按本阶段的验收项计算，总百分比按所有验收项计算。例如库级锁通过第一项时，该阶段是 1/2（50%），总进度是 1/19（5.3%）。零项通过时显示空轨道。[进度条模板](assets/bar.svg)

`agent/visuals/` 保存当前计划的 `plan-progress.svg`（PLAN）和 `plan-progress.png`（聊天）。试排时用 `--plan` 指向临时目录内的样例计划，完成后清理该目录。
