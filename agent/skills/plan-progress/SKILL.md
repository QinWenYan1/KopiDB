# 计划进度条

有当前计划时，每轮修改、检查或汇报都调用本技能。只维护协作工具时同样展示业务计划的实际进度。以 PLAN 中的 `[x]` 和 `[ ]` 计算验收数。[逐函数计数约定](../goal-to-plan/SKILL.md#4-给阶段配验收标准)

1. 按本轮实际结果更新复选框和阶段状态。草案、排版预览或技能维护沿用业务计划的实际完成数。
2. 在最终答复正文中直接使用下方样式。引用块依次放任务名与百分比、一行行内代码字符条、已完成项数。字符条固定 20 格，按完成比例用 `█` 填充，其余用 `░`。百分比以清单计算结果为准，保留至多一位小数。进度条只出现在聊天正文，仓库保存 PLAN 清单。
3. 引用块后放完整阶段表。表头沿用“阶段 / 任务与改动 / 已完成 / 完成度 / 状态”。每个阶段都占一行，包括尚未开始的阶段。描述同时交代该阶段的目的和主要修改位置。
4. 业务实施时，在表下按[逐函数的代码排版](../lab-workflow/SKILL.md#4-一次讲清一个函数)展开本轮步骤。维护或收尾时只说明实际改动与当前准备状态。详细验收记录由助手维护，遇到需要用户处理的问题就指出具体位置。

```markdown
> **可串行化实现　　　　　　　　　38.1%**
>
> `████████░░░░░░░░░░░░`
>
> 已完成 **8 / 21** 项
```

示例中的 8/21 仅演示排版，实际汇报替换为当前清单的数据。读取 `agent/PLAN.md` 中的进度标记区域，按阶段统计复选框。代码块内的示例不参与计数。

阶段百分比按本阶段的验收项计算，总百分比按所有验收项计算。零项通过时整条显示 `░`，所有项通过后才填满。用聊天的原生 Markdown 展示，用户可以直接在正文中看到完整进度。
