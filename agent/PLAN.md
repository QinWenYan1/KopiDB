## 本轮衔接规则

1. **先收集，再判断，再重放。** `WAL::recover` 返回检查点之后所有事务的记录，包括 ROLLBACK 和未结束事务；管理器需要这些信息登记失效版本、延续 ID。返回 map 不代表其中每个事务都允许重放。
2. **检查点是连续安全前缀。** 不能拿最大的零散已刷盘 ID 直接过滤全部较小事务；独立的已刷盘 ID 仍由上层进一步判断。
3. **回滚沿用版本过滤。** RU 数据可能已经在 SST 中，仅不重放该事务不足以让它失效；恢复时须接通现有回滚集合，不重新引入旧值回写。
4. **恢复期间保留旧 WAL。** 重放到内存不等于已经持久化。初始化新文件不能删除恢复仍需的记录，也不能直接把检查点设置成 next ID 减一。推进清理检查点前，必须满足数据与恢复所需事务状态的保存条件。
5. **启动时执行恢复。** 此时尚未启动新的 WAL 清理线程，也不接收并发用户操作；不为静态 recover 增加无效的对象锁。

## 阶段①方案与验收场景

`WAL::recover()` 的第一轮草案：

- 目录不存在返回空 map；空路径与现有 WAL 构造函数一致，表示当前目录。
- 只识别普通文件 `wal.<十进制数字>`，使用 uint64_t 序号，先解析再排序，避免每次比较重复解析。
- 每个文件一次读取，按 Record 的小端长度字段定位完整记录的末尾，再交给现有严格 `Record::decode` 解码。
- 崩溃可能留下不足 2 字节的长度头，或声明长度大于文件剩余字节的末条记录：报告警告，只在读取缓冲中排除这段尾部。旧日志保留后，多次重启可能再次遇到同一尾部，因此不限制为最新文件。
- 长度小于公共头、完整记录的非法类型／负载以及文件读取失败仍抛异常；不使用 catch-all 把损坏文件当作空日志。当前格式没有校验和，尾部容错不代表能识别任意字节损坏。
- 只保留 ID 大于检查点的记录，移动进相应 vector，保留完整提交／回滚记录和操作先后顺序；不更改文件内容，不在本函数登记事务状态。

## 当前函数：TranManager::check_recover()

修改位置：`src/lsm/transation.cpp:1102`；在同文件标准头文件区域显式补充 `<algorithm>`、`<limits>`。保留当前签名，由后续 LSM 构造函数在对外服务前调用；此时尚未初始化新的 WAL，也没有活跃用户事务。

本轮草案沿现有成员实现：

1. 持有管理器互斥锁，取 flushed 集合首项作为连续检查点，调用已验收的 WAL::recover。
2. 综合状态文件恢复的 next ID、flushed／ready／aborted 中的 ID，以及 WAL 中的最大 ID，计算不会重复使用的下一个 ID；不能用回滚 ID 或未结束 ID 再创建新事务，最大 ID 无法加一时明确报错。
3. 在 ready／aborted 副本里处理结果。现有写入路径把结束记录放在事务日志末尾；末条为 COMMIT 且未在回滚名单中的事务保留，尚未结算者登记为 OP_COMMITTED；ROLLBACK 或没有完整 COMMIT 的事务加入回滚名单，尚未结算者登记为 ABORTED，并从返回 map 移除。
4. 保留状态文件已有回滚信息，不清空名单；全部处理成功后交换容器并更新 next ID。不要持锁调用内部还会加同一把锁的状态登记函数。
5. 返回已提交事务候选。零散已刷盘事务仍可出现在返回 map 中，由阶段④依据 flushed 集合跳过重放；此函数不将仅有日志的提交登记为已刷盘，不改写／删除 WAL，不提前保存推进后的清理检查点。

与作者对照：作者参考这里只调用 WAL::recover 并返回 map；本地选择回滚 ID 过滤方案，因此分类和恢复过滤名单是本轮必要衔接。现有静态 recover 保证返回的每组记录非空并保持事务内顺序，管理器不重复解码字节。
